# Chinese-Style Mobile Gacha RPG Systems: New Servers, Gacha Events, Dice/Spin/Lottery Events, Promotions, Packages, FOMO, and Progression-Based Monetization

> **Purpose:** This document describes the broader event ecosystem found in Chinese-style mobile gacha RPGs and similar live-service hero-collector games, with explicit Pokémon-style examples.
>
> The examples below are **fictional Pokémon-game implementations** used to explain the systems. They are not claims that an official Pokémon game uses these exact mechanics.

---

# 1. The Big Picture

The "new server" system is only one part of a much larger live-service machine.

A typical Chinese-style gacha RPG can have several overlapping layers:

```text
                         LIVE SERVICE GAME
                                │
          ┌─────────────────────┼─────────────────────┐
          │                     │                     │
     NEW SERVERS            PERMANENT SYSTEMS     LIMITED EVENTS
          │                     │                     │
   ┌──────┼──────┐        ┌─────┼─────┐       ┌─────┼──────────┐
   │      │      │        │     │     │       │     │          │
 Rush   Rankings  Server   Gacha PvP  Guild   Spin  Dice     Lottery
 Events          Goals
   │
   ├── Level Rush
   ├── Power Rush
   ├── Campaign Rush
   ├── Summon Rush
   ├── Spending Rush
   ├── Recharge Rush
   ├── Collection Rush
   └── etc.
```

The important thing is that these systems are **designed to overlap**.

A player might simultaneously be:

- trying to reach Trainer Level 60;
- trying to reach Arena Master;
- trying to become #1 in Team Power;
- trying to finish a Summon Rush;
- trying to complete a limited Pokémon banner;
- trying to spend Gems before a Gem Consumption event ends;
- trying to reach a recharge milestone;
- deciding whether to buy a limited package;
- saving resources for tomorrow's event;
- and worrying that today's offer will disappear forever.

That overlap is what makes these games feel extremely event-dense.

# 2. New Servers

## 2.1 What a new server actually is

A new server is effectively a **fresh competitive ecosystem**.

Instead of placing a new player into a three-year-old environment, the game creates:

```text
Server 101
Server 102
Server 103
Server 104
...
```

Each server begins at a particular launch time.

A new server might open:

- every few hours;
- every day;
- every few days;
- whenever the previous server reaches a target population;
- or as part of a scheduled launch wave.

The exact cadence depends on the game's population and monetization strategy.

---

# 3. Why Games Keep Creating New Servers

A mature server creates a massive progression gap.

Imagine:

### Server 001

A player has:

- 50 fully developed Pokémon;
- max-level gear;
- millions of Gems spent;
- maxed Arena ranking;
- years of accumulated resources.

A new player cannot realistically compete.

A new server resets the competitive environment:

```text
NEW SERVER
     ↓
Everyone starts weak
     ↓
Everyone needs resources
     ↓
Everyone is racing
     ↓
Leaderboards become meaningful
     ↓
Players spend to gain an advantage
```

This is one reason "new server rush" and monetization are so tightly connected.

# 13. Pity Systems

A pity system guarantees or improves the chance of obtaining a target after enough attempts.

Example:

```text
1–49 summons:
Normal rates

50 summons:
Increased Legendary chance

100 summons:
Guaranteed Legendary

200 summons:
Guaranteed Featured Pokémon
```

A Pokémon game might call this:

> **Master Ball Guarantee**

---

# 14. Soft Pity

The probability can gradually increase.

Example:

```text
Summon 1–50: 2%
Summon 51–75: 4%
Summon 76–99: 8%
Summon 100: 100%
```

This encourages players to continue once they are "close."

# 20. Gacha + Ranking Event Combination

This is where the systems become powerful.

Suppose:

> **Summon Rush**

is active.

Every summon gives ranking points.

```text
1 summon = 1 point
10 summons = 10 points
100 summons = 100 points
```

Now a player who wants the featured Pokémon has another reason to summon **during this specific period**.

The same summon can therefore accomplish:

```text
Get Pokémon
+
Build pity
+
Earn summon points
+
Climb Summon Rush
+
Complete milestone
+
Earn event currency
```

That stacking of objectives is a defining pattern of dense mobile-event design.

```text
→ 100 points

Spend 5,000 Gems
→ 500 points

→ 1,000 points
```

# 22. Why Gem Spending Events Are Powerful

Imagine a player has saved:

> 50,000 Gems.

Normally they might spend them whenever they want.

Then the game announces:

> **GEM CONSUMPTION FESTIVAL — 48 HOURS**

Now the player thinks:

> "I should wait and spend my Gems during this event."

This changes the player's spending behavior without necessarily requiring a new resource.

### Paid Gems

Purchased with real money.

### Free Gems

Earned through gameplay.

### Bonus Gems

Granted by promotions.

Cannot be transferred or used in certain systems.

> **6,480 Gems!**


# 29. FOMO — Fear of Missing Out

This is a major design principle.

FOMO means:

> The player feels they may lose an opportunity if they do not act now.

Examples:

```text
ENDS IN 03:14:52
```

or:

> "Only available during the first 7 days."

or:

> "Exclusive to Server 101."

or:

> "This offer will never return."

or:

> "Only 2 hours remaining."

---

# 30. Healthy vs Aggressive FOMO

FOMO itself is not a single mechanic.

It can be relatively mild:

> "This cosmetic is available for two weeks."

Or aggressive:

> "This package expires in 15 minutes and will never return."

A well-designed game can create urgency without misleading players.

# 118. Important Ethical / UX Note

These systems can be extremely effective, but there is a meaningful distinction between:

**Clear, honest urgency**

and

**manipulative or misleading pressure.**

For a player-friendly implementation:

- show exact expiration times;
- clearly disclose whether rewards are random;
- clearly show gacha probabilities;
- make pity rules visible;
- don't falsely claim something will "never return" if it may return;
- make paid/free currency distinctions clear;
- don't hide important purchase conditions;
- give players ways to plan around upcoming events;
- avoid deliberately obscuring the real monetary cost.

You can still have exciting limited-time events without making the interface deceptive.

# 119. Short Terminology Summary

If you need to describe the complete system to a developer, designer, or AI:

> **New Server / Server Opening System:** creates fresh servers with their own temporary progression ecosystem.

> **New Server Rush / 开服冲榜:** time-limited competitive leaderboards attached to the server launch.

> **Gacha Event:** limited or permanent randomized Pokémon acquisition banners.

> **Gem Consumption Event:** rewards players for spending premium currency during a specific window.

> **Recharge Event:** rewards players for purchasing premium currency.

> **Spin / Wheel Event:** randomized reward wheel using free or purchased spins.

> **Dice Event:** board progression using dice rolls.

> **Lottery Event:** ticket-based randomized prize system.

> **Growth Fund:** upfront purchase that unlocks rewards as the account progresses.

> **Level-Gated Package:** offer unlocked when the player reaches a particular account level.

> **Power-Gated Package:** offer unlocked at a combat-power threshold.

> **PvP-Gated Package:** offer unlocked after reaching an Arena/PvP rank.

> **FOMO:** urgency created by limited availability, deadlines, exclusive rewards, or expiring opportunities.

> **Event Stacking:** one player action simultaneously progresses several event systems.
